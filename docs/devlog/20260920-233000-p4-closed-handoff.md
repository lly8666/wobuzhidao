## P4 最终覆盖

- Logical Tunnel / stable Account+Installation lease / source anti-spoof。
- Normal=1；Game=2/3/4，PacketID racing + tunnel-wide dedupe，不做跨包条带化。
- protected admission 明确 `lane_id=1..4`，每 lane 独立 FakeTCP association。
- same-ID replacement：失败candidate保留旧generation；成功路径具 A->A+B->B、generation fencing、retiring bound。
- 自动 rotation timer：无需调用方手动RotateOldest，generation前进并收敛回desired physical lanes。
- payload idle：ACK、repair/runtime/lifecycle tick不刷新idle；client/server自动DORMANT；下一真实业务自动wake。
- DORMANT/wake/rotation均保持同一个 leased TunnelOwner、TunnelID、IPv4 lease、InstallationID。
- tunnel-wide padding budget默认off，具每record与累计比例/总量限制；无额度立即跳过。
- Linux shared-TUN + iptables/nft privileged；Windows Wintun + Npcap hosted seam；OpenWrt IPv4 TPROXY + transparent SocketAdapter。
- 单进程client/server entry与raw/Npcap endpoint seam；不恢复old Controller、localhost UDP、DTLS shim或platform-proxy子进程拓扑。

## P5 交接边界

本提交不启动P5代码。新agent从P5开始前必须先读仓库authority与required read set。

P5是新版本fullstack弱网/负载/长测与受控真实HTTPS外观/成本验收：
- 覆盖首个外层连接与已建lane上的后续HTTPS连接；
- 稀疏单连接、自然并发、不同证书链、完整/恢复握手；
- FEC off / 实际启用挡位，无损 / 既定弱网；
- 采集outer packet与TLS-like record长度、方向、时间间隔、突发字节、往返节奏；
- 分开capture loss、网络drop、FEC、repair、padding；
- 记录goodput/app loss/duplicate/RTT p50/p95/p99/post5恢复、CPU/host busy、内存/GC、队列峰值/驻留、drop位置、wire amplification；
- padding生产继续默认0/off；能力正确性/成本与生产启用决策分开；
- 正常HTTPS仅作外观参考，不做旧项目A/B；
- 若做分类分析，按独立站点/会话分组并报告来源、误报/漏报与适用范围，禁止同一会话切片泄漏训练/评估；
- 不从少量样本宣称不可识别。

P4到此停止。下一条产品代码应由新agent作为新的P5原子任务开始。
