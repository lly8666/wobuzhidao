## 新发现问题

同一原始日志显示 `TestKernelTLSFallbackVerifiedHTTPAndNormalClose` 用时60.24s。业务/pcap断言早已完成，延迟出现在defer `server.Close -> endpoint.Close -> wg.Wait`：Linux上另一个goroutine阻塞的AF_PACKET `Recvfrom` 不保证仅靠跨goroutineclose立即唤醒。这违反本轮“取消/关闭释放等待者和计时器应有界”的目标，即使功能job为绿也不能据此关闭P2。

## 修改

- `RawIPv4Endpoint` recv socket设置200ms `SO_RCVTIMEO`；idle时只做有界wake检查，不参与发包节奏，不是随机sleep。
- endpoint记录closed状态；Recvfrom超时后若已关闭返回 `net.ErrClosed`，否则继续等待真实packet。
- kernel fallback测试在所有FIN/association清理断言后显式调用 `server.Close`，要求<=1s；defer仍作为失败路径兜底。
- 不修改faketcp稳态恢复、tlsrecord、FEC、MTU、Game或P3目录。
