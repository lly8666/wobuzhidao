## 修改与原因

### active FEC core

从归档 live path 提取到 `internal/fec/`：
- `fec.go`
- `fastcodec.go`
- `fastblock_encoder.go`
- `block.go`
- `completed_blocks.go`
- `recovery.go`
- `decoder_observe.go`

保留 live FEC v1 56-byte `WF` header。parity byte 是 authoritative geometry，固定 K=20，R 允许 4/8/10/12/16/20。没有启用归档 `profile_block.go/profile_codec.go/profile_fastcodec.go` 的 v2 平行 wire：归档自身注释仍把它描述为待 admitted 的 profile path，而 live `control.CurrentLinkPolicy` + `linkdata.Path` 已经通过 v1 header 支持完整 fixed matrix。

systematic source 继续在 `Add` 时立即发送，不等 block 满或 flush。full block 发送 R 个 repair；partial N-source block 发送 min(N,R) 个 repair。

decoder 保留 heavy maxBlocks、compact retired state、8192 retired hard bound、late systematic first-arrival 和 completed-history compaction。新增 active conflicting duplicate shard payload 检测：相同 shard identity + 相同 payload 幂等；相同 identity + 不同 payload 返回 `ErrShardMismatch`，不覆盖 first arrival。

### LINK/FEC 接线

新增 `internal/linkdata/fec_path.go`：
- LINK 只分片一次，fragment frame 在 FEC 前；
- FEC source 首到立即进入 LINK reassembler；
- 每个 path/lane 独立 encoder/decoder/recovery state；
- 3 秒 recovery deadline 从 first heavy observation 起绝对计时，进展和重复不刷新；
- 显式 `Expire(now)` 支持停流后的 timer retirement；
- expiry 后保留 compact first-delivery state，late systematic 仍可首次交付一次；
- adapter 返回 owned immutable FEC wire copy。

最后一点是新根 ownership 收口：归档 FastBlockEncoder 的低层 API 返回复用 backing slot。若一个 65535-byte 逻辑 datagram 分出超过 20 个 LINK fragment，而上层先累计所有 wire 再发送，第二个 FEC block 会重用第一个 block 的 encoder slot。新 FECPath 在返回产品 wire 时复制所有权，避免先前待发送 wire 被后续 Add 改写。

## 问题、排查与风险

- 本轮 FEC SourceMTU 是接口输入，不是统一 outer MTU authority；P3 后续仍需 pathmtu 统一推导 record/FEC/LINK 预算。
- FEC v1 active heavy state 可比较 conflicting duplicate payload；compact retired state故意不保存旧 payload，只保留 bounded delivery identity，因此不会为无限期 duplicate payload 比较重新扩大内存。
- 当前没有 steady-state FakeTCP recovery 接线，不能把 FEC unit/LINK adapter 资格解释成完整弱网数据面。
- wrong-lane 防护仍由 lane owner/association ownership 提供；FEC wire 不新增 lane ID，也不建立跨 lane 共享 decoder。
