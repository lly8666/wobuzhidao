## Why a pinned WFP lab instead of pretending persistence
Previous Go-only WFP `FwpmEngineOpen0/FwpmLayerGetByKey0` tests prove only read-only access. Product must maintain IPv6/physical DNS anti-leak filters **even if the process dies while the host keeps /1 Wintun routes**. Prototype a real persistent filter on controlled GitHub Windows runners before designing the actual guard. To avoid hand-writing opaque FWPM_FILTER0 pointer/union ABI, pin `github.com/tailscale/wf v0.0.0-20240214030419-6fbb0a674ee6`, BSD-3-Clause license, published and reused by Tailscale; pin exact old `go4.org/netipx` indirect dependency and Go hashes. Do not re-enable old/ module.
`internal/windowsclient/native_wfp_persistent_lab_windows_test.go` is explicitly env opt-in for isolated Actions: `WBD_N4_WFP_ISOLATED_LAB=1`. It opens non-dynamic native WFP engine sessions, creates unique random persistent GUID sublayer and rule, with BLOCK limited to documentation TEST-NET IPv4 203.0.113.254 at unusual destination port 65530, closes session, opens fresh engine, verifies same rule persists with ActionBlock on IPv4 ALE_AUTH_CONNECT and `Persistent=true`, then deletes rule/sublayer by exact GUID and reports success. Error cleanup always tries a fresh WFP engine and never touches foreign WFP rules. Both Windows2022 and 2025 hosted runners; Go Bash workflow, no PowerShell scripts.
**Do NOT run on user's Windows machine.** This is a controlled hosted *rule persistence and ownership LAB* only. It does not install broad IPv6/DNS leak rules or protect the live client; no default product code calls this. A successful job means scoped WFP persistence possible and cleaned, NOT that N4 DNS/IPv6 anti-leak is already implemented.
