## 修改与原因

新增internal/tlsrecord/vector_test.go。

固定向量来源不是待测Encode函数：SOURCE_SHA 65184f80的Linux Actions先运行独立tools/tlsrecordvector。该程序不import internal/tlsrecord，而是直接按WIRE_SPEC调用SHA-256/HKDF/ChaCha20-Poly1305/ChaCha20 primitive。Actions日志与artifact给出固定context hash、c2s/s2c AEAD/IV/HP keys，以及PN=0、1、2^32+1、uint64 max-1、uint64 max的完整wire bytes。本测试把这些十六进制值作为静态expected常量。

新增断言：
- Exporter context hash与双向76字节派生材料逐字节匹配独立reference。
- 五个PN边界的完整wire逐字节匹配reference，并用OpenRecord反解验证PN/payload。
- 同key/PN/plaintext重复primitive seal结果逐字节相同，固定record层不可变字节性质。
- 先收PN=2^32+1再收PN=0，证明不存在highest-PN接收窗口或跨包HOL。
- 认证失败后再收到同PN合法record仍可交付，证明失败不写近期去重状态。
- 显式1..4字节短payload返回ErrInvalidLength；空FakeTCP payload视为没有record。

不修改协议格式、加密选择、缓存容量或其他阶段模块。
