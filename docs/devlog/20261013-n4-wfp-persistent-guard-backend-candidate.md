## Candidate backend built on pinned BSD3 tailscale/wf
`internal/windowsclient/native_wfp_guard_windows.go` implements an **unconnected** native CrashPersistentGuard backend with installation-scoped stable SHA256-derived owner GUIDs, non-dynamic WFP sessions and *persistent* owned Sublayer/Rule entries. `Arm` checks existing WFP sublayer/rule IDs, refuses any unknown/foreign object, installs missing owned sublayer and three candidate rules, closes and reopens WFP engine to Verify after installing. `Verify` on an independent session requires all three persistent BLOCK filters, correct WFP ALE V6 outgoing/incoming and V4 DNS port53 layers, exact non-tunnel LUID predicates/flags, and correct stable names, not just rule IDs. `Disarm` must confirm exact owner conditions before reverse deletion and avoids deleting unrelated user filters. The library supports round-trip enumeration of WFP fields and uses non-dynamic session. Type implements CrashPersistentGuard but is unexported and not wired into main windows runtime.
**Multi-tunnel hazard:** a separate filter per allowed Wintun LUID would block other Wintun sessions, so backend requires an explicit `ExclusiveSingleWintun` attestation and otherwise is not Durable. This does not yet make it production-qualified. Design global shared Wintun allowlist or conservative single-active-tunnel rejection before activating in CLI.
Pure Windows tests check no mutation when read-only absent installation, cancellation before Arm/Disarm and foreign rule action/conditions/owner rejection. Extend hosted TEST-NET WFP persistence lab to compare EVERY returned WFP field against the original rule after engine reopen via the same strict n4WFPRuleEqual; this probes whether actual Windows/WFP library values roundtrip correctly and whether guard would falsely accept a foreign policy.
