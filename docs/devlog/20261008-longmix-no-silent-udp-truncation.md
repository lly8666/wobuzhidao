# Minimal product candidate: never silently shorten oversized Linux UDP mapping reply

SOURCE baseline `b4ea061178a6e09b7e7c8587d72b4b8535492567`, new isolated product fix branch `investigation/longmix-no-udp-truncation-20261008`. Frozen ref not moved; this commit is **not** a retroactive correction of b4 A/p0 FAIL. In b4 Linux OpenWrt TPROXY/protocol-specific platformflow: max payload is `logicaltunnel.MaxLeasedIPv4PacketLen(9000)-IPv4HeaderSize(20)-FrameHeaderSize(44)=8936`. The current server `UDPServer.readUpstream` read with `buf=MaxPayload` and forwards truncation, violating strict rejection correctness. This change switches to exactly `MaxPayload+1` bytes, drops a whole oversize datagram, increments bounded atomic `upstream_oversize_drops`, and continues processing later datagrams. Linux TPROXY ingress similarly records oversized/`MSG_TRUNC` drops and continues; no attempt to lift field limit, increase FEC/buffers/recovery time, alter generation or mutably track data bytes.

New Go unit test uses ordinary real UDP socket on loopback (functional-only): 96, exactly MaxPayload, MaxPayload+1, 8972, 8973, 65507, subsequent 256 to catch next-datagram contamination and ensure explicit reject for all payload sizes over the current limit; snapshot counter check. Workflow on independent branch runs product Go unit, race and client/server build **only in GitHub Actions**, not on development device or physical machine. Still needs result; do not claim PASS until run finishes, no fullstack/performance qualification from functional tests. Because max legal UDP 65507 > Linux platformflow cap by design, this minimal guard merely fixes silent S2C truncation; remaining >8936 UDP delivery is OPEN and must not be erased as expected reject from the A mixed workload denominator.

The original Windows->Linux ARM real TUN large UDP 1225.578ms remains a distinct OPEN bug, as does the first 80s one-way S2C outage. Native Windows/ARM and B/C/other loss samples are not covered by this small patch; expected metadata SHA belongs to this new commit, not baseline b4.
