## Candidate code, limits and defaults
1. `Runtime.Tick` now invokes `tickControl` instead of sequential `tickHealth` then `tickQuality`. A successful 104B or 128B quality emits a genuine `IdleFor` and also restarts ordinary health's successful 15s (configured interval) timer; the AEAD-authenticated receive lane ALREADY parses both v2/v3 as HealthMessage with ordered PN and writes it to `observeHealthLocked`. Thus removing duplicate health at source does not remove receiver idle sync. No two controls in same Tick. Under old/non-V3 admission, quality disabled falls back to the original mandatory strict **9B** health; forced idle/FIN notices bypass the periodic scheduler.
2. N1 source quality is no longer unconditional each 2s. First report is a bounded bootstrap; subsequently a genuine changed post-Emit fresh KindLINK PN window, local DATA drop, peer reported sender watermark, maturity status change, estimated missing change or 3.5s recent-business freshness deadline is needed. Comparing peer reportSeq alone never causes echo-ping-pong. Last received data window does not get stamped as a new sample just because a scheduled Tick occurred. Regular eligible control delay initial jitter 1.5–2.0s with independently sampled crypto random value (conservative subset of user-requested ~1.5–2.5s); upon no new observation suppress and recheck only 500ms later, without new packet. No extra worker/goroutine/business callback scan; 256-slot RX/TX snapshot only when scheduling an eligible quality control decision.
3. Successful ordinary keepalive uses configured interval with ±10% jitter, sampled only upon successful control record Emit; failed attempts do NOT touch next successful health time or count as received. Independent bounded 1s retryAfter prevents Tick hot loop or health fallback immediately after quality Emit error. Missing authenticated hints never mean idle: `PeerIdle` retains PN-ordered hint freshness and 2× keepalive interval, genuine business IdleFor callback unchanged. Control/FakeTCP ACK/repair never rewrite client business idle clock. Close/forced idle still possible.
4. `tlsrecord.SealHealthWithPadding` adds explicit control-only KindHealth AEAD inner_type+zero padding, preserving zero-padding original ciphertext byte-for-byte, original PN/replay fields and exact FakeTCP same-Seq full-ciphertext repair. `TunnelOwner.ControlHeadroom` returns exact current active direction outer safe room `txBudget.RecordWireMTU - tlsrecord.FixedWireOverhead(31) - body`. `ControlHealthRecord` strictly checks exactly 9B v1 / 104B v2 / 128B v3 body and protected nonce/local gen on v2/v3. It clips requested padding to bounded legal room, rejects base overflow/negative, then SEALS just once under existing lane TX mutex; KindLINK business/seal/FEC/4096/fragmentation untouched. Authenticating decoder already strips existing encrypted zero pad before strict format-length checks. Current maximum fill is bounded by negotiated record cap + real configured outer IPv4/TCP option headers and peer MSS, no implied IPv6 outer support.
5. Two small internal `runtimeowner.TransportConfig` fields: `ControlPaddingDisabled` default false, `ControlPaddingMaxBytes` default 0 meaning full safe headroom; valid explicit cap 1..16384. **Not yet available as user CLI/JSON flags**: source-of-truth CLI `PARAMETERS.json` remains generated by existing program; wiring official Linux/Windows/server CLI in a separate atomic commit with verified catalog is REQUIRED before marking the full user-requested UX complete.
