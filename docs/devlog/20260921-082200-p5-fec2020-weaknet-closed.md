## Same-seed comparison with FEC off

The FEC-off baselines use the same scenario seeds and deterministic loss generator. FEC changes the emitted packet sequence, so these are controlled same-seed scenario comparisons, not packet-paired samples.

Absolute repair retransmit counts increased by about 70-93%, largely alongside the increased emitted packet volume. Normalized by network attempts, repair/attempt increased by about 2.5-8.0%, so 20:20 did not eliminate the transport repair path.

The 20:20 resource samples showed heap-allocation peaks around 16.5-16.7 MB and host-busy observations around 0.39%-0.97% depending on runner. These resource values are observational only and are not compared as an absolute cross-VM performance gate.

## Interpretation boundary

This result shows a strong latency/recovery/application-success benefit for fixed 20:20 in these hosted 300 ms loss scenarios, at a large wire/PPS cost. It is an explicit capability/cost measurement, not a production FEC recommendation. Production default remains FEC off.
