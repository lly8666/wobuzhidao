## 修改与原因

新增 `internal/pathmtu/budget.go`。

保留旧实现的：
- operator-visible connection MTU 范围 576..9000；
- 下层不得再施加 1360/1400/1500 历史 cap；
- wrapper 必须逐层消费预算；
- 负容量/无法容纳启用协议头时配置阶段 fail closed。

替换旧实现的：
- 不再固定假设 IPv4/TCP=40；调用者传实际 steady-state IPv4/TCP header 长度，分别要求 20..60 且 4-byte 对齐。
- 不再用 DTLS13RecordReserve=32；直接使用 active `tlsrecord.FixedWireOverhead=31`。
- 不再依赖旧 `control.CurrentLinkPolicy` 或 `gamepath`。
- FEC 开启时使用 active FEC v1 `HeaderSize=56`；所有 live 20:4/8/10/12/16/20 挡位 MTU 开销相同。
- LINK fragment envelope 固定 20 bytes。
- peer MSS 进入同一个公式；peer 没发 MSS 时沿用 P2 已固定的 IPv4 effective MSS=536。
- protected admission 的 direction-specific record wire limit 进入同一个公式。
- 可选 local packet MTU 只作为比 operator connection MTU 更小的实际 ceiling，不形成第二个 operator 配置。

核心公式：

```text
effective_packet = min(connection, local_if_smaller)
packet_payload   = effective_packet - ipv4_header - tcp_header
carrier_payload  = min(packet_payload, effective_peer_mss)
record_wire      = min(carrier_payload, negotiated_record_wire_limit)
record_payload   = record_wire - 31
link_frame       = record_payload - (FEC ? 56 : 0)
fragment_payload = link_frame - 20
```

要求 `link_frame > 20`；否则明确拒绝。

## 风险与边界

- 当前只实现 IPv4 steady-state budget；IPv6 外层仍未实现，不假设 IPv4 开销可直接复用。
- 预算接收 actual TCP header 长度，但当前 P2 steady-state data serializer 尚未接完整恢复 options；未来如果 data packet 真发送 SACK/timestamp 等 options，owner 必须传真实 header 长度。
- `local_packet_mtu` 是运行时/平台实际 ceiling，不是第二个可独立调参的产品 MTU。
- 本轮只证明预算与现有 LINK/FEC/tlsrecord API 可组合；还没有 session/owner 把 admission negotiated limit、association peer MSS 和实际 serializer header 自动接入。
