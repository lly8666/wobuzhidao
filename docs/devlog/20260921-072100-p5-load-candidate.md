## Scope

This starts only the prescribed P5 load atom at 5/10/15/20 Mbps. The target is explicitly **aggregate inner application payload, C2S + S2C**.

The atom does not include the later 40 Mbps aggregate-inner capacity exploration, 50/100 Mbps exploration, >=30 minute soak, FEC tuning, or padding enablement.

## Workload

- One established formal outer Normal lane and one persistent BusinessFlow.
- Real inner TLS 1.3 and HTTP/1.1.
- Persistent POST/echo transactions with deterministic payload integrity.
- Bidirectional mixed payload cycle: 1 KiB, 8 KiB, 32 KiB request body and same-size response.
- 15 second fixed offered-load window.
- Absolute-clock pacing from cumulative offered bits; no batching wait.
- FEC off, padding off, no network loss/delay injection.

Each load rate runs twice with independent deterministic payload seeds. Actions matrix dimensions are rate and run, so every matrix entry is one VM / one load / one seed / one artifact.

## Measurement and validity

Raw artifacts retain outer PCAP/events plus load and resource JSONL. The validator independently recomputes:

- offered/accepted/actual application bytes,
- send failures, skipped slots and send lag,
- application loss/duplicates/integrity,
- RTT p50/p95/p99,
- fixed-window PPS,
- inner TLS wire bytes and outer wire amplification,
- repair inventory,
- FEC/padding/capture-loss separation,
- CPU aggregate/per-core, memory/GC and transport queue peaks.

The application pacing lag is reported as scheduler-queue residency. CPU/PPS/memory are observational only; there is no cross-VM absolute resource gate.

For a load run to qualify as PASS, actual aggregate application payload must be at least 95% of the offered bytes, with no application corruption/loss/duplicate or send failure. A lower achieved rate is reported as CAPACITY_LIMITED or INJECTION_UNDERRUN instead of being hidden or blamed generically on the runner.
